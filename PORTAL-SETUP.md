# TAD member portal

The original landing page is unchanged except for Account and Albums links. Its stylesheet and image assets are unchanged.

## Service boundary

GitHub Pages serves the public website. Firebase Authentication handles accounts; Firestore stores contact information and album metadata. No contact workbook, contact export, user password, service-account key, or authentication token belongs in this repository. Firebase web configuration is public identification, not an administrative credential.

This implementation uses Spark-compatible Authentication and Firestore features. It does not use Cloud Functions or Cloud Storage, and does not send newsletters. Album editors choose existing site photos or supply direct HTTPS image URLs; image files stay with their host. Faculty copy semicolon-separated addresses into Outlook. Newsletter lists require explicit opt-in; On Hold and Removed records are excluded from all prepared lists.

## Access

| Role | Own profile | Contact directory | Contact/status editing | Albums |
| --- | --- | --- | --- | --- |
| Member | Read/edit after email verification | No | No | Published albums only |
| Faculty | Read/edit after email verification | Read/filter/export/copy emails | No | Create/edit/publish |
| Admin | Read/edit after email verification | Read/filter/export/copy emails | Yes | Create/edit/publish |

Roles live in private `roles/{authUserId}` documents. Nobody can choose their role when registering. Only admins can grant another account access; admins cannot change their own role. The initial three admins and three faculty are provisioned outside the public repository. Their email addresses/passwords are not part of the client code. Existing accounts must verify their email address before accessing profiles or staff features. Password changes and email password resets are available on the account page.

The directory's “connection” field is self-reported context, not an access role or confirmation of board appointment. Status and internal notes are stored separately from member-editable profiles. No hard-delete action is exposed; use Removed or On Hold and unpublish albums as appropriate.

## Configure

1. Create a dedicated Firebase project on **Spark**, without linking billing. Register its web app.
2. Enable Authentication → Email/Password. Add `bsutad.github.io` to authorized domains. Set a minimum password length of 8 or higher.
3. Create a Firestore **Standard** database in production mode. Deploy `firestore.rules` and `firestore.indexes.json` before enabling registration.
4. Fill `portal-config.json` with the public web configuration. An empty configuration fails closed and disables registration.
5. Provision the named accounts and initial private role documents through a trusted administrator workflow. Do not mark an email verified without verification. Users can use “Resend email” after signing in.
6. Configure Firebase App Check for the web app and put its public site key in `appCheckSiteKey` before enforcing it in Firebase. Check the legitimate traffic metrics before enforcement.

## Local development and verification

`npm ci`, `npm run build`, `npm test`, and `npm run test:rules`.

The rules suite uses the Firebase emulator and synthetic identities only. It checks public/private boundaries, cross-member access, faculty edit denial, admin status and access changes, protected fields, album publishing, and invalid image links. Java 17 is supported by the pinned Firebase CLI 14 used for these tests; upgrade Java before moving to CLI 15.

`npm run serve` opens a local static server on port 4173. The committed bundle is `portal.js`; regenerate it with `npm run build` whenever `src/` changes. Page markup is generated by `scripts/pages.mjs`. Deploying `main` updates GitHub Pages.

## Workbook key

`src/key.js` transcribes the labels, meanings, and fill colors from sheet 2, **Status Key (DRAFT)**, of Advisory Key.xlsx. Student counts and faculty assignments are intentionally not part of the signup form. Lighter badges use dark text for contrast while retaining the supplied fill colors. The first sheet's private contacts have not been imported or published.

## Maintenance

Keep a periodic CSV export of the private directory in an approved private location. CSV exports include profile fields, areas, status, and newsletter preference; they do not include passwords. Firebase Spark has usage limits and can stop requests when exhausted rather than charging. There is no automatic backup or outbound-email workflow in this version.
